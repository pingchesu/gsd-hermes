# Plan 8.2-02: Execute-Phase Provider-Routed Dispatcher Workflow

<objective>
Update `/gsd-execute-phase` orchestration so `workflow.agent_execution_router = "provider-cli"` consumes SDK `agent_execution_bindings`, prints explicit execution receipts, preflights the selected driver, and dispatches executor/verifier work to the correct CLI path without allowing `cross_ai_execution` or ad-hoc fallback prose to override valid provider-routed bindings.
</objective>

<context>
This plan connects the Phase 8.1 SDK receipt and Plan 8.2-01 command renderer to the real execute-phase workflow. The user-facing contract is strict:

- `model_overrides.gsd-executor = "openai/gpt-5.5"` must run executor work through Codex CLI (`codex exec --model gpt-5.5`).
- `model_overrides.gsd-verifier = "anthropic/claude-opus-4-7"` must run verification through Claude Code CLI (`claude -p --model claude-opus-4-7`).
- If the chosen driver is unsupported, missing, or unusable, the workflow must fail before execution with a fix suggestion.
- Legacy `workflow.cross_ai_execution` remains a whole-plan fallback only when provider-routed direct binding is absent/disabled or explicitly forced; it must not override a valid `provider-cli` binding.
</context>

## Task 2 — Add provider-cli dispatch branch before Task/delegate fallback

type: implementation
files: `get-shit-done/workflows/execute-phase.md`

action:
- In the executor spawn section, insert provider-cli dispatch logic before the current `Task(subagent_type="gsd-executor")` examples.
- If `agent_execution_bindings.router == "provider-cli"`:
  1. Select `agent_execution_bindings.agents.executor` for executor plans.
  2. Require `status == "resolved"` and `execution_driver` in `{claude-cli,codex-cli}`.
  3. Write the full executor prompt to a temporary prompt file under `.planning/tmp/provider-cli/` or equivalent ignored temp path.
  4. Call the Plan 8.2-01 helper to preflight and render the command.
  5. Execute the selected driver with prompt delivered via stdin or a shell-safe prompt path, never by interpolating prompt text into command strings.
  6. Treat non-zero exit as plan failure and route to the existing failure handler.
- Keep worktree behavior conservative for provider-cli in this phase:
  - If provider-cli execution cannot safely use Claude `isolation="worktree"`, run provider-cli dispatch sequentially on the current working tree and say so in the receipt.
  - Do not pretend Codex/Claude CLI spawned through shell has Claude Code `Task()` worktree isolation.
- Preserve checkpoint heartbeats around plan start/complete/failure.

verify:
- Workflow text contains explicit `provider-cli` branch before Task fallback.
- Workflow text says provider-cli shell execution is sequential unless a later phase adds safe external worktree orchestration.

acceptance_criteria:
- When provider-cli router is enabled, executor dispatch no longer uses `executor_model` to guess `Task(model=...)`.
- OpenAI executor binding cannot end up in the Claude `Task()`/`claude -p` fallback unless SDK binding itself selected `claude-cli`.
