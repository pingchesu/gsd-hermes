# Plan 8.2-01: Provider CLI Command Renderer and Preflight Contract

<objective>
Create a small, credential-free provider CLI dispatch helper that converts SDK `agent_execution_bindings` entries into safe command/preflight metadata for `/gsd-execute-phase`. This plan provides the code-level seam used by workflow markdown and tests so provider routing is not re-guessed from raw model strings.
</objective>

<context>
Phase 8.1 added `sdk/src/query/agent-execution-router.ts` and `init.execute-phase` output:

- `openai/gpt-5.5` → `execution_driver: codex-cli`, `cli_model: gpt-5.5`
- `anthropic/claude-opus-4-7` → `execution_driver: claude-cli`, `cli_model: claude-opus-4-7`
- unsupported/unknown → `execution_driver: unsupported`, diagnostic and suggested_fix

Phase 8.2 must not duplicate provider-family regexes in workflow markdown. It should consume `agent_execution_bindings` and fail fast if the selected driver is unavailable or unsupported.
</context>

<tasks>

## Task 1 — Add provider CLI dispatch helper

type: implementation
files: `get-shit-done/bin/lib/provider-cli-dispatch.cjs`

action:
- Add a CommonJS helper that accepts one `AgentExecutionBinding`-shaped object plus runtime options (`workdir`, `prompt_path`, `agent_role`, `agent_name`, optional timeout).
- Export pure functions, at minimum:
  - `renderProviderCliCommand(binding, options)`
  - `renderProviderCliReceipt(binding)`
  - `preflightProviderCliDriver(binding, env?)`
- `renderProviderCliCommand` must only branch on `binding.execution_driver`, not on `configured_model` string patterns.
- For `claude-cli`, render an argv array equivalent to:
  - `claude -p --model {cli_model} --agent {agent} --permission-mode acceptEdits < {prompt_path}`
- For `codex-cli`, render an argv array equivalent to:
  - `codex exec --model {cli_model} --full-auto -C {workdir} < {prompt_path}`
- Include a safe shell display string using proper quoting, but keep argv as the canonical execution representation.
- Unsupported/null/invalid bindings must throw an actionable error containing `execution_driver`, `agent`, `configured_model`, `provider_family`, and `suggested_fix` if present.

verify:
- A direct Node snippet can import the helper and render both driver commands without invoking the CLIs.
- OpenAI bindings render `codex exec`, not `claude -p`.
- Anthropic bindings render `claude -p`, not `codex exec`.

acceptance_criteria:
- Command rendering consumes binding fields and does not inspect raw model tokens to select a provider.
- The returned structure contains `driver`, `argv`, `display`, and `receipt`.
- The helper is credential-free and deterministic.

## Task 2 — Add CLI wrapper for workflow use

type: implementation
files: `get-shit-done/bin/gsd-provider-cli-dispatch.cjs`, `package.json`

action:
- Add a small CLI wrapper around the helper so workflow markdown can call it from shell snippets.
- Suggested interface:
  - `node get-shit-done/bin/gsd-provider-cli-dispatch.cjs receipt --binding-json "$BINDING_JSON"`
  - `node get-shit-done/bin/gsd-provider-cli-dispatch.cjs command --binding-json "$BINDING_JSON" --prompt-path "$PROMPT" --workdir "$PWD"`
  - `node get-shit-done/bin/gsd-provider-cli-dispatch.cjs preflight --binding-json "$BINDING_JSON"`
- Add package metadata/bin entry only if existing conventions support internal helper CLIs; otherwise keep it as a private script path and document the path in the workflow.
- Preflight should check command availability with `command -v claude` / `command -v codex` semantics and return non-zero with clear setup text when missing.
- Authentication checks should be conservative and credential-free: avoid running real model calls in normal preflight. If help/version checks are used, they must be bounded and not require network.

verify:
- `node get-shit-done/bin/gsd-provider-cli-dispatch.cjs command ...` prints expected command metadata for fixture bindings.
- Missing/unsupported binding returns non-zero and actionable stderr.

acceptance_criteria:
- Workflow can shell out to one helper instead of embedding command rendering logic in prose.
- Preflight failures occur before any plan prompt is executed.
