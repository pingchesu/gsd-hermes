# Plan 08.4-01: Docs, Gates, and Release Readiness

## Objective

Document the v1.8 provider-routed agent execution contract in operator-facing language and prove the repo is ready for a later release/publish task without publishing from this phase.

The completed milestone should make the intended behavior obvious:

```text
model_overrides.gsd-executor = "openai/gpt-5.5"
→ provider_family=openai
→ execution_driver=codex-cli
→ codex exec --model gpt-5.5

model_overrides.gsd-verifier = "anthropic/claude-opus-4-7"
→ provider_family=anthropic
→ execution_driver=claude-cli
→ claude -p --model claude-opus-4-7
```

and equally clear that unsupported providers or unavailable CLIs fail fast instead of silently falling back.

## Context

Phases 8.1–8.3 already implemented and tested the runtime behavior:

- 8.1 added SDK `agent_execution_bindings`.
- 8.2 added provider-cli command rendering/preflight and execute-phase workflow routing.
- 8.3 added credential-free regressions and Hermes validation gates.

Phase 8.4 is intentionally documentation and release-readiness only. Do not add new runtime semantics unless a doc gate exposes a small naming/validation mismatch.

## Tasks

### 1. Update configuration documentation

Edit `docs/CONFIGURATION.md` to document:

- `workflow.agent_execution_router = "provider-cli"`.
- Supported provider families in v1.8:
  - Anthropic/Claude → `claude-cli` → `claude -p --model {cli_model}`.
  - OpenAI/GPT → `codex-cli` → `codex exec --model {cli_model}`.
- Example `.planning/config.json` snippet with:
  - `model_overrides.gsd-executor = "openai/gpt-5.5"`.
  - `model_overrides.gsd-verifier = "anthropic/claude-opus-4-7"`.
- Fail-fast behavior for unsupported providers and missing CLI/auth setup.
- `workflow.cross_ai_execution` remains a legacy whole-plan fallback and does not override provider-cli direct binding.

Keep the docs explicit enough for operators to copy/paste and then manually adjust values.

### 2. Update Hermes compatibility documentation

Edit `docs/hermes-compatibility.md` to distinguish two proof levels:

- **Provider-routed CLI enforcement:** GSD selects the driver and passes the normalized CLI model argument (`codex exec --model ...` or `claude -p --model ...`). This proves deterministic command routing, not wire-level API routing inside external CLI tools.
- **Hermes native delegate_task model proof:** Hermes `delegate_task(model=...)` child-construction proof only applies when the native delegate path is used; it is separate from provider-cli execution.

Also document that provider-cli mode is the recommended strict route when operators need different agents to run under different provider CLIs.

### 3. Update README and command docs

Edit `README.md` and `docs/COMMANDS.md` with concise operator language:

- Mention provider-routed agent execution in the Hermes/runtime section.
- Show the two core examples: OpenAI executor → Codex, Claude verifier → Claude CLI.
- State the guarantee: matching driver or fail-fast, never silent fallback to another provider CLI.
- Avoid claiming full wire-level upstream provider proof.
