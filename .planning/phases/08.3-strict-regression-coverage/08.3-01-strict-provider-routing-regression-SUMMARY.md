## What changed

Added credential-free regression coverage for the v1.8 provider-routed execution contract.

### SDK / init coverage

- Expanded `tests/agent-execution-router.test.cjs` to cover bare provider-family tokens:
  - `gpt-5.5` → `openai` → `codex-cli` → `gpt-5.5`
  - `claude-opus-4-7` → `anthropic` → `claude-cli` → `claude-opus-4-7`
- Added `tests/hermes-provider-routing-regression.test.cjs` to execute the live repo fixture:
  - `node bin/gsd-sdk.js query init.execute-phase 8.3`
  - verifies current `.planning/config.json` produces:
    - executor: `openai/gpt-5.5` → `codex-cli` / `gpt-5.5`
    - verifier: `anthropic/claude-opus-4-7` → `claude-cli` / `claude-opus-4-7`
- Added negative checks that the init payload does not contain degraded runtime notes that reroute OpenAI bindings through Claude CLI.

### Command renderer coverage

- Strengthened `tests/provider-cli-dispatch.test.cjs` so:
  - OpenAI/Codex bindings cannot render `claude`, `claude -p`, or `--agent`.
  - Anthropic/Claude bindings cannot render `codex`, `codex exec`, or `--full-auto`.
  - `cli_model` is required before command rendering.
  - shell display quotes prompt/workdir paths with spaces and apostrophes while keeping prompt content out of command argv.

### Hermes compatibility guardrails

- Added workflow static guardrails to `tests/hermes-provider-routing-regression.test.cjs` and included that test in `scripts/validate-hermes-compat.cjs`.
- The Hermes compatibility gate now fails if `execute-phase.md` loses provider-cli dispatch semantics, receipt/proof-boundary wording, or lower-priority `cross_ai_execution` behavior.
