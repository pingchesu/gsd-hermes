# gsd-hermes v1.5.0 — Upstream get-shit-done 1.38.5 Sync

## Summary

`gsd-hermes@1.5.0` syncs the Hermes downstream fork with upstream `get-shit-done-cc@1.38.5` while preserving the GSD-first workflow model and Hermes runtime adapter semantics. The release keeps the downstream npm package identity (`gsd-hermes`), Hermes dash-form command discovery, SDK/CJS parity, and strict runtime/model binding receipt behavior introduced in v1.4.30.

## Upstream changes imported

- SDK executor summary placement and plan-content loading fixes.
- Full installed prompt loading and `/gsd-<cmd>` routing suggestion improvements.
- Parent `.planning/` root resolution for sub-repos.
- Shell hook version substitution/detection fixes.
- Lint protection against source-grep tests.
- Markdown anchor discovery, codebase map refresh output, and installer local SDK-check skip updates.

## Downstream preservation

- `gsd-hermes` package metadata and installer messaging stay downstream-owned.
- Hermes-owned docs continue to present `/gsd-<cmd>` dash-form commands as canonical.
- Runtime/model binding receipts remain strict: explicit per-agent model config must either bind through the Hermes child construction path or fail fast with actionable diagnostics.
- Provider proof boundaries remain conservative; no release note claims provider wire-level enforcement without sanitized provider request evidence.

## Fixes made during validation

- CJS and SDK valid model-profile selectors now both include `inherit`.
- Structured `parallelization` config objects are preserved across CJS config normalization and SDK golden parity.
- `package-lock.json` is synchronized with the upstream dependency surface.
- `scripts/base64-scan.sh` avoids per-line process spawning on large upstream files while preserving decoded prompt-injection detection.
