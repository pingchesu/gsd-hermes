### Granularity adaptation (D-15 schema relaxation)

D-15/D-16 specify per-hunk rows in the sync log. Plan 03's actual scope (226 unmerged
files vs planner's 29-file estimate) made strict per-hunk logging infeasible for the
bulk `upstream base` batch. Adaptation applied:

- **`bin/install.js`**: per-hunk rows retained (56 entries from Plan 02's
  `/tmp/bin-install-hunks.txt` — Hermes adapter seam at the heart of the fork
  deserves full hunk-level auditability).
- **`Hermes adapter seam` files other than bin/install.js (8 files)**: per-file
  rows (not per-hunk). Each file is a whole-file `kept ours` or `took upstream`
  decision based on cross-cutting Hermes-v1.2 architectural commitments
  (runtime-model-contract, MODEL_PROFILES superset, build-from-source install).
  Hunks within each file are subordinate to the whole-file routing decision.
- **`downstream governance` files (5 files)**: per-file rows. Each file's
  resolution is a governance-level whole-file decision.
- **`upstream base` files (213 files)**: per-file rows with `took upstream`
  resolution. These are pure `--theirs` applications — no per-hunk judgment was
  applied, so per-hunk rows would contain no additional information beyond
  "took upstream verbatim" for every hunk.

This adaptation trades per-hunk granularity for tractability at 226-file scale
while preserving the D-17 public-safe property (no hunk content copied; file:line
refs only) and the Pattern C ownership-terminology contract.
